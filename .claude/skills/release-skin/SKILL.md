# 새 스페셜 스킨 출시

스킨 하나를 일반 버전에 공개할 때 하는 일을 순서대로 적었다. 스킨 효과 코드(`app/src/Woodada/Sprites/Skins/<이름>Skin.cs`)는 이미 있고 개발용 빌드에서만 보이는 상태라고 본다. 효과를 새로 만드는 일은 이 스킬 범위가 아니다.

진행할 때 단계마다 할 일을 작업 목록에 올리고, 끝나면 아래 "마지막 보고"대로 무엇을 했고 무엇이 남았는지 알린다. 커밋·푸시·태그는 사용자가 말할 때만 한다.

## 0. 먼저 사용자에게 묻는다

공개 범위는 사용자가 정한다. 짐작해서 고르지 않는다.

- **어떤 스킨**을 공개하는지. 후보는 `RewardCatalog.Skins`에서 `Released`가 `false`인 것들이다.
- **버전 번호.** 보통은 마이너 버전을 올린다(예: v1.4.0 → v1.5.0). `git tag --sort=-v:refname | head -3`으로 지난 태그를 보고 제안한다.
- **쓰레드 글을 쓸 언어**: 한국어만, 영어만, 둘 다 중에서.
- 프로필 문구(한마디·특기·버릇·좋아함·싫어함)는 초안을 만들어 보여 주고 사용자가 고친다. 지어낸 문구라는 것을 밝힌다.

함께 알려 줄 것:
- 뽑기 확률은 같은 등급 스킨끼리 나눈다(레어 60 : 에픽 30 : 전설 10). 예를 들어 레어를 하나 더 풀면 유령냥이 나올 확률이 절반이 된다. 화면에는 확률을 어디에도 적지 않는다.
- 도감을 다 모은 사용자는 "모두 모았어요"가 풀리고 뽑기 버튼이 다시 켜진다.

## 1. 앱

1. `app/src/Woodada/Rewards/RewardCatalog.cs`에서 그 스킨의 `Released`를 `true`로 바꾼다. 위 주석에 적힌 공개 목록("1.0.0에 공개한 것: …")도 맞게 고친다.
   - 이것만으로 도감·고양이 탭 스킨 줄·뽑기 후보에 들어간다. 모두 `RewardCatalog.AvailableSkins`를 쓰기 때문이다.
   - 도감 칸을 누르면 홈페이지 프로필(`ExternalLinks.SkinProfileUrl`)이 열린다. 공개한 스킨만 열리니 따로 고칠 것은 없다.
2. **NEW 표시**는 저절로 붙는다. 코드를 고칠 것은 없고, 동작만 확인한다(2026-11-16 결정).
   - 앱이 켜질 때 처음 보는 공개 스킨을 기록 파일 `rewards.json`의 `skinsFirstSeen`에 적는다. 그날부터 `RewardCatalog.NewSkinDays`(7일) 동안 새 스킨으로 친다. 출시일이 아니라 이 PC가 처음 본 날 기준이다.
   - 표시되는 곳: 아직 없는 도감 칸과 고양이 탭 스킨 줄 칸에 체리색 NEW 배지가 붙고, 실루엣에 그 스킨의 `Accent` 색이 은은하게 밴다. 이름은 계속 "???"이고 **등급은 공개하지 않는다.** 냥뽑기 탭 이름 옆에는 빨간 점이 뜨고, 탭을 한 번 열면 꺼진다.
   - 꺼지는 때: 그 스킨을 뽑았거나 7일이 지났을 때. 뽑기 연출 중에는 정체가 드러날 때까지 NEW를 그대로 둔다.
   - 처음 설치한 사람에게는 NEW가 붙지 않는다. `RewardCatalog.SkinsBeforeNewMarks`(유령·플래시·글리치)에는 **새 스킨을 더하지 않는다.**
   - 확인 방법: 개발용 냥뽑기 탭 아래 개발용 바의 "NEW 다시 켜기"를 누른다. 그러면 아직 없는 스킨이 모두 방금 나온 것으로 바뀌고, 다른 탭으로 갔다 오면 빨간 점도 보인다. 배지와 색 힌트가 새 스킨 색에서 잘 보이는지 본다. 바탕에 묻히면 `Accent`를 조정한다.
3. **레이아웃 확인** (`app/src/Woodada/UI/SettingsWindow.cs`)
   - 스킨 줄(`BuildSkinRow`): 기본 모습 칸 + 공개 스킨 수만큼 칸이 같은 너비로 나뉜다. 칸이 좁아져도 고양이와 효과가 칸 안에 들어오는지 본다. 꼬리·서리·새끼처럼 뒤로 길게 끌리는 스킨은 `DrawSkinTileArt`의 `cx` 오프셋 목록에 넣는다.
   - 도감(`DexColumns = 4`): 공개 스킨이 4개를 넘으면 두 줄이 된다. 창 높이(일반 버전 804)에서 잘리거나 스크롤이 생기지 않는지 본다.
   - 뽑기 무대·도감에서 쓰는 색이 몸과 바탕에 묻히지 않는지 본다. 플래시냥을 체리색으로 보여 주는 것처럼 따로 색을 정해야 할 수 있다.
4. **일반 버전 화면 확인**
   - 설치된 진짜 Woodada와 그 데이터는 건드리지 않는다. Release 빌드를 로컬에서 띄우지 않는다.
   - 개발용(`app/dev.cmd`, 맥은 `app/dev.sh`)은 모든 스킨을 보여 준다. 일반 버전 모습을 보려면 `AvailableSkins`를 잠깐 `Skins.Where(s => s.Released).ToList()`로 바꿔 띄워 보고, **반드시 되돌린다**.
   - 영어·한국어로 하나씩 본다: 이름, 별, 등급, 설명, 뽑기 연출(당첨 → 결과 줄 → 입히기).

## 2. 홈페이지 (`docs/`, GitHub Pages)

앱의 스킨 값을 그대로 옮긴다. 이름·등급·설명은 `RewardCatalog`와 같아야 한다. 등급 이름은 앱 표기를 따른다(레어·에픽·전설 / Rare·Epic·Legendary).

1. **그리는 코드** (가장 큰 작업)
   - `docs/cats/cats.js`: `SKINS`에 새 항목(무대 그림 + 능력치 계산)을 넣는다. 공유 이미지용 멈춘 한 장 `POSTER`와 도감 썸네일(`drawThumb`)도 넣는다.
   - `docs/site.js`: "스페셜 스킨 시작"과 "스페셜 스킨 끝" 주석 사이에 같은 효과를 넣는다. 메인 페이지 카드의 `data-skin`으로 그린다.
   - 값과 공식은 `<이름>Skin.cs`에서 그대로 가져오고, 주석에 원본 파일 이름을 적는다. 두 파일에 코드가 겹치니 둘 다 고친다.
2. **프로필·도감 페이지**
   - `app/tools/cat_pages.py`의 `CATS`에 한 칸을 더한다. 넣을 것: id(= `RunnerSkins.ToId`), 이름, 별, 한마디, 소개, 짧은 소개, 힌트, 눈금, 능력치 4줄, 특기, 버릇, 좋아함, 싫어함. 모두 영어·한국어를 함께 쓴다.
   - **두 마리가 서로 주고받는 스킨**(털실냥의 패스처럼 CPU·메모리 고양이가 함께 입었을 때 상호작용이 있는 것)만 `"duo": True`를 넣는다. 그 페이지에만 1P·2P 단추가 생기고, 처음엔 두 마리가 달린다. 그 스킨의 `cats.js` 항목은 `pair: true`로 두 마리를 한 번에 그린다(`yarn` 참고). 상호작용이 없는 스킨은 넣지 않는다(늘 한 마리).
   - 도감 순서는 앱 `RewardCatalog.Skins` 순서를 따른다.
   - 도감 끝의 "곧 만나요!" 칸 수 `LOCKED`는 남은 미공개 스킨 수가 아니라 예고 칸 수다(지금 1). 미공개 스킨이 남아 있으면 그대로 두고, 하나도 없으면 0으로 한다.
   - 도감 공유 이미지 설명 `alt`("Ghost Cat, Flash Cat and Glitch Cat …")를 고친다.
   - `docs/cats/cats.css`에 `body[data-cat="<id>"]`의 이름 글자 색 `--name-a`~`--name-d`를 넣는다.
   - `python app/tools/cat_pages.py`를 돌린다. 그러면 `docs/cats/<id>/index.html`이 생기고 `docs/cats/index.html`이 갱신된다.
3. **메인 페이지** `docs/index.html`: 냥뽑기 섹션 `.skins`에 `<article class="skin" data-rarity="…">` 카드 하나를 도감 순서대로 더한다. 기존 카드와 같은 모양으로, "프로필 보기 →" 링크(`cats/<id>/`)까지 넣는다. 카드 줄은 flex로 가운데 맞춤이라(데스크톱 3칸, 1080px 이하 2칸) 카드 수가 나누어떨어지지 않아도 마지막 줄이 가운데에 온다(2026-11-19 다꾸냥 때 5장 → 3 + 2). 넓은 화면과 휴대폰 너비에서 한 번씩 본다.
4. **공유 미리보기 이미지** `app/tools/cat_og.py`
   - `NAME_COLORS`에 cats.css와 같은 색을 넣는다.
   - 도감 전체 이미지(`key == "all"`)는 고양이 x 위치가 세 마리 기준으로 박혀 있으니 마릿수에 맞게 다시 배치한다.
   - `python app/tools/cat_og.py`를 돌린다(Chrome이나 Edge 필요). `docs/assets/og/<id>.png`와 `cats.png`가 나온다. 이미지를 열어 직접 본다.
     - 스크립트는 모든 고양이 이미지를 다시 찍는다. 그림이 그대로인 다른 고양이 PNG도 파일 바이트가 달라지니, 바뀌지 않은 것은 `git restore`로 되돌려 커밋에 섞지 않는다.
     - 효과가 몸 밖으로 크게 나가는 스킨(털실·다꾸냥 스티커)은 고양이 한 장 그림에서 이름·한마디 글자와 겹치지 않는지, 도감 그림에서 옆 고양이 효과를 가리지 않는지 본다. `drawPoster`의 `count`처럼 그림 쪽에 줄일 수단을 둔다.
5. **로컬 확인**
   - `docs/`를 로컬 서버로 띄운다: `python -m http.server -d docs`, 또는 `.claude/launch.json`에 등록해 미리보기 도구를 쓴다.
   - 볼 곳: 메인 카드, `/cats/`, `/cats/<id>/`, 영어·한국어 전환, 휴대폰 너비, 콘솔 오류.

## 4. 릴리즈

1. 커밋 제목은 한국어로, 사용자가 읽을 수 있게 쓴다. 릴리즈 본문이 "이전 태그 이후 커밋 제목 목록"(`.github/workflows/release.yml`)으로 만들어지기 때문이다.
2. **순서**: main에 앱과 홈페이지 변경을 함께 푸시한다 → 태그 `vX.Y.Z`를 푸시한다.
   - Pages 배포가 릴리즈 빌드보다 빨라서, 사용자가 업데이트할 때쯤엔 프로필 페이지가 이미 떠 있다. 그래야 도감에서 누를 때 404가 나지 않는다.
   - 태그를 홈페이지보다 먼저 올리지 않는다.
3. 버전은 태그에서 나온다. csproj의 `<Version>0.0.0</Version>`은 그대로 둔다.
4. 배포가 끝나면 실제 주소 `https://hyuntae-jeong.github.io/Woodada/cats/<id>/`가 열리는지, 공유 미리보기가 뜨는지 본다.

## 5. 쓰레드 소개 글

- 초안은 `promo/<id>/threads.md`에 쓴다. `promo/`는 git이 무시하는 개인 홍보 폴더다.
- 글은 사용자가 직접 올린다. 대신 올리지 않는다.
- 구성
  - 첫 줄에 새 고양이 이름과 한 줄 매력(사용률에 따라 어떻게 변하는지)을 쓴다.
  - 얻는 법: 냥뽑기, 생선 500개. 확률은 쓰지 않는다.
  - 프로필 페이지 링크를 넣는다(공유 미리보기가 뜬다). 업데이트는 앱이 알아서 받는다고 적는다.
- 첨부할 이미지
  - `docs/assets/og/<id>.png`를 쓴다.
  - 움직이는 모습이 필요하면 프로필 무대를 녹화하라고 제안한다. 직접 녹화할지는 사용자에게 묻는다.
- 사용자 말투를 따른다. 짧게 쓰고, 이모지는 한두 개만.

## 6. 기록 갱신

- 자동 메모리 `next-release-skins.md`의 공개 목록·일반 버전 칸 수·남은 후보를 고친다.
- 자동 메모리 `project-handoff.md`의 진행 상황 표에 새 버전을 더한다.
- 이번 출시에서 이 스킬에 없던 단계가 생겼거나 틀린 곳이 있으면 이 파일을 고친다.

## 마지막 보고

- 단계별로 한 것, 하지 않은 것, 사용자 몫으로 남은 것을 나눠 적는다. 사용자 몫은 문구 확인, 커밋·푸시·태그, 쓰레드 게시다.
- 확인하지 못한 것은 그대로 적는다. 예: 맥에서 본 모습, 실제 업데이트 후 화면.
